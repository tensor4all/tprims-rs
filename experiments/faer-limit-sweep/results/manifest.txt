faer-limit-sweep: the planner's faer route against the packed driver on
copy-free fusable contractions, per dtype, per thread count and per C mode

Measured library revision
  New run: tprims-rs bf2c868 (branch exp/faer-limit-accumulate, based on main
  bf2c868). Earlier run: tprims-rs 4e02ba0 (branch exp/faer-limit-sweep, based
  on main 4e02ba0). Both measure crates/tprims-contract's planner:
  PlanConfig::default() (faer below the dtype's FaerLimit, packed above it) and
  PlanConfig::packed(), the subject of tprims-rs#63 / #69. strided-view 12ff2de9
  (=0.4.6), the revision main pins; faer 0.24.4; rayon 1.12.0. No file in
  crates/, benchmarks/ or docs/ changed.
  The earlier sessions were recorded before the probe source had a final
  `rustfmt` pass and one `#[allow(clippy::too_many_arguments)]` attribute; both
  are formatting/lint only, no token or code path changed. The new sessions
  were likewise recorded before a final `rustfmt` pass on the extended probe
  (formatting only). The new run is on the
  newer revision, so a ratio read across the earlier and the new table mixes
  that change; the new run's own `absent` and `output` rows are same-revision.

C modes
  absent  CSpec::Absent, beta = 0, Plan::execute_into: D = alpha * A * B into a
          zero D (the overwrite form the earlier run used).
  output  CSpec::Output(Op::Identity), beta = 1, Plan::execute_into_accum with
          AccumulationSource::Output: D = alpha * A * B + beta * D in place over
          a non-zero D (the MPS-step form, D += A*B).
  alpha = 1 in both. The `output` reference is alpha * sum(A*B) + beta * D_old,
  computed from the labels exactly as the absent oracle is, on a non-zero
  starting D.

Probe
  experiments/faer-limit-sweep, own workspace, excluded from the root
  workspace.

Command
  bash experiments/faer-limit-sweep/run.sh 3
  One binary records both C modes; run.sh [sessions] is the single entry point.
  Each sub-run writes results/cmode-session{s}.{csv,txt,guard}.

Timed boundary
  Per call, only the plan execution, on a prebuilt Plan (planner default, or
  packed forced) and a preallocated output. Problem construction, planning, view
  construction and buffer allocation are outside the clock. One arm is measured
  at a time:
    absent  Plan::execute_into.
    output  Plan::execute_into_accum(.., AccumulationSource::Output).
  In the output mode the priming and timed calls accumulate into the same D
  without a reset between calls (as a sequence of MPS steps does); the per-call
  cost is the same.
    1T  Exec::serial(); the process is pinned to one CPU.
    4T  a host-owned rayon::ThreadPool of 4 workers, built once before the
        timed region, borrowed through tprims_exec::Pool::borrow and handed to
        Exec::rayon. The binary asserts the pool width, the Exec budget and
        that Cpus_allowed_list holds exactly the requested CPUs, and refuses
        RAYON_NUM_THREADS / OMP_NUM_THREADS / OPENBLAS_NUM_THREADS /
        MKL_NUM_THREADS / VECLIB_MAXIMUM_THREADS that contradict --threads.
  Correctness: every case is checked against a naive label oracle and the two
  arms against each other before any timing (rel < 1e-10 for f64/c64, < 1e-5
  for f32/c32); a mismatch aborts the run. The CHECK lines are in each
  cmode-session*.txt (368 per session: 23 shapes x 4 dtypes x 2 C modes x 2
  thread counts); the earlier session*.txt carry 184 per session, absent only.
  Worst rel over the new run: absent 1.13e-6, output 1.11e-6 (f32/c32 rows);
  rel_arms <= 4.6e-7. No case failed.

Shapes (column-major contiguous; labels as in experiments/three-engine-contract)
  gemm         D[i,k] = sum_j A[i,j] B[j,k], n in {32, 64, 128, 256}
  gemm_batched D[i,k,b] = sum_j A[i,j,b] B[j,k,b], (n,batch) in
               {(16,16),(32,16),(64,16),(32,64),(64,64)}
  mps_env      ab,asc->bsc: A = chi x chi, B = chi x 2 x chi, D = chi x 2 x chi
  mps_site     bsc,bsd->cd: A = B = chi x 2 x chi, D = chi x chi
               chi in {16, 24, 32, 48, 64, 96, 128}
  Every class is measured in DType::{F32, F64, C32, C64}. `mnk` is the fused
  `m * n * k` per batch item, the quantity the planner's FaerLimit compares; it
  is read from the packed plan's PlanStats for both arms and both C modes.

Statistic
  Best of 5 calls per arm per session, after 500 ms of untimed wall-clock
  priming per arm (the same wall-clock warm-up on both arms, so the shorter one
  is not biased by a call count). The table reports the median over the 3
  sessions, and spread = (max-min)/median of the 3 per-session values, the
  larger of the two arms' spreads.

Host
  AMD Ryzen AI 9 HX 470 (Zen5 APU), 12 physical / 24 logical cores. Two L3
  domains: cpus 0-3,12-15 share 16 MiB; cpus 4-11,16-23 share 8 MiB. Every
  measured set was in the latter. cpufreq governor powersave. rustc 1.99.0
  (b940084d7 2026-09-28), release profile opt-level 3 + thin LTO +
  codegen-units 1, default target CPU. Linux.

Guard
  benchmarks/scripts/pinned.sh of the measured checkout, one guarded, pinned
  process per (session, thread count). 1T picks its CPU with
  `idle_cpus.py pick 1 --seconds 3`; 4T picks with `idle_cpus.py pick 4`. The
  guard log records the window (3 s), the threshold (busy <= 0.05) and the SMT
  siblings it checked. All six sub-runs of the new run passed at attempt 1
  ("idle before and after"); see results/cmode-session*.guard. All six sub-runs
  of the earlier run also passed at attempt 1; see results/session*.guard.
  Nothing else was built or measured while a session ran; the cargo build
  precedes the sessions. CPU sets, new run: every session ran 1T on cpu4 and 4T
  on cpu4,5,6,7.

Result
  results/cmode-session{1,2,3}.csv hold 736 rows each (23 shapes x 4 dtypes x
  2 arms x 2 thread counts x 2 C modes, one ns per row); their .txt hold the
  CHECK lines and their .guard the guard logs. results/session{1,2,3}.* hold the
  earlier absent-only run (368 rows each). README.md carries the summary tables
  and the per-class ratios.

What this does not cover
  - One host, one rustc, one session order, and two library revisions across the
    two runs. A laptop APU under `powersave`: no fixed frequency, no isolated
    cores.
  - Only two C modes: `absent` (overwrite) and `output` (in-place accumulation,
    beta = 1, Op::Identity). CSpec::Separate is not measured; nor are other beta
    values, op_C conjugation or alpha != 1.
  - Whole-shape timings only: no split between packing, the micro-kernel and
    write-back inside either engine, and no counter-based attribution.
  - The `mps_env` output shape follows the label order of the equation
    (`bsc` -> chi x 2 x chi), not the "2 x chi x chi" written in the task text.
  - For c64 above the provisional limit both arms are the packed driver: the
    default route already switches at mnk = 262144, so those rows are an A/A of
    one engine, not a faer/packed comparison. The c64 crossover is observable
    here only below that volume.
  - Routing observed in the new run: default = faer/`fused` for all f32/f64/c32
    and c64 below the limit; packed/`above_faer_limit` above it. NotFusable,
    AllBatch and elementwise never appeared; the routing is identical in both C
    modes.
  - No FaerLimit value is chosen or recommended here.
